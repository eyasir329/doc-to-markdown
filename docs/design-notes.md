# Design notes

This is the project's engineering log. It was written while the pipeline was built and measured, and it records
why things are the way they are, usually with the measurement that decided it. It's meant for contributors and
for anyone curious about the details. Users will find what they need in the guides in this folder.

Read it as a log:
- Where an older note disagrees with a newer one, or with the guides, the newer note and the code are current.
- Numbers are from Kaggle's 2×T4 machine in November 2026.
- "Case NN" and "the Doc2MD test suite" refer to a private 27-page test document (one hard case per page). It
  contains personal data, so it isn't published.
- *Make Electronics* and *Trees, Maps, and Theorems* are published books that were used as long real-world tests.

## Production hardening (v1.0.0)

- **Abandoned jobs are cancelled.** A client that was killed (a timeout in a script, a closed laptop) left its job
  running: one full-suite job ran 27 minutes beside the next one and slowed it down. Every status poll, part
  upload and chunk steal now marks the job as seen. A job that no client has asked about for `MD_ABANDON_MIN`
  (15) minutes is cancelled: one still in the queue is never started, and one already running is stopped.
- **The client cancels its jobs when it is stopped.** Ctrl+C already did. Now SIGTERM and SIGHUP (closing the
  terminal, `kill`, a supervisor's stop) do too.
- **Upload parts can't fill the disk.** A part is refused (`413`) as soon as it grows past the declared file size,
  for jobs and for stored files.
- **Security basics, re-checked:**
  - the token is compared in constant time (`hmac.compare_digest`);
  - job and file IDs are generated by the server;
  - download paths are resolved and must stay inside the job's folder;
  - zip archives are checked for path traversal, file count and unpacked size;
  - at start, the notebook stops if the API answers a request that has no token.

## Quality modes: measurements and decisions

One setting chooses how much vision-LLM work a job gets. It is `--quality` on the client, or `QUALITY` in the notebook's `JOB_DEFAULTS` (default `balanced`). Each stage can still be switched on its own (`--no-review`, `--no-describe`).

| Stage | fast | balanced | accurate |
|---|---|---|---|
| Marker + Surya OCR, figure crops, tables checked against the image, drawn formulas as pictures, **text-layer repair**, Indic repair, tidy-up (no LLM) | yes | yes | yes |
| Figures cropped to the figure itself, figure descriptions | yes | yes | yes |
| Flow diagrams read as a graph → Mermaid | 1 answer | 2 answers + missing-arrow check | 3 answers + missing-arrow check |
| Marker's own LLM steps (tables, equations, headings) | no | yes | yes |
| Marker's inline-maths rewrite | no | no (the page review does it) | yes |
| Page review (rewritten only if nothing is lost) | no | whole page at once | **section by section** (≤ 900 tokens each), each with its own lines of the PDF text |
| Page review skipped when the PDF's own text settles the page completely (every word from it, nothing of it missing, no maths/code/table) | – | yes | no |
| Pictures of text (a newspaper page, a letter: kind `text`/`screenshot`, ≥ 1000 px) transcribed tile by tile, not only described | no | yes | yes |
| **Line-by-line audit** (the model lists exact corrections; each one is applied only if the PDF's text confirms it or a second look at the image picks it, and never where the PDF's text has the old wording) | 1 pass, 12-paragraph sections | 1 pass, 8-paragraph sections | **2 passes**, 6- then 3-paragraph sections |

The figure descriptions and the page review run at the same time, since both only wait for the LLM, so the LLM's slots stay full.

On test-suite pages the audit found what the whole-page review kept missing: Chinese OCR look-alikes (数字李生 → 数字孪生, 音服热线 → 客服热线), `\sqrt[2]{2}` for the printed `\sqrt{2}`, and `y^n` for `y^m`. It also lists "fixes" that change nothing, and sometimes wrong ones; those are dropped or refused.

Measured on the 27-page Doc2MD test suite (2 × T4 box, 4 workers, 2026-11-23, before the fixes below):

| | fast | balanced | accurate |
|---|---|---|---|
| Wall time | **342 s** | 875 s | 1042 s |
| Box worker time (Marker / describe+review / audit) | 639 / 304 / – s | 1676 / 851 / – s | 1494 / 1045 / 721 s |
| Test-suite checks | 54/59 | 55/59 | **57/59** |
| Text coverage | 98.4% | 98.4% | 98.0% |
| Mermaid charts, equations | none, 29 display | 2, 35 | 2, 29 |

- **fast** keeps all the text (the same coverage) and every check that only needs OCR. It has no Mermaid charts, no review, and so OCR'd maths is not corrected (the Case 26 equation fails), and no figure-only crops.
- **balanced** adds Marker's LLM steps (most of its extra time is the Marker stage), the page review and diagram charts.
- **accurate** adds the audit (8 fixes confirmed, e.g. 数字李生 → 数字孪生, `\sqrt[2]{2}` → `\sqrt{2}`). In that run it also "completed" words the page itself cuts off ("Figure 2.1 T" → "Figure 2.1"). Since then a fix is refused when the page's text has the old wording verbatim. A paragraph longer than a section no longer makes the whole page keep its draft. Marker's inline-maths rewrite (`REDO_INLINE_MATH`) now runs only in accurate, because the page review already rewrites inline maths in balanced. This is the largest Marker-stage cost; re-measure with the script below.

Speed without giving up accuracy (all qualities):
- **Nothing waits for nothing:** the figure descriptions run beside the page review (or, in fast, beside the audit). Each page goes into the audit as soon as its own review is done, not after the slowest page's, and the sections of a page are audited side by side.
- **The audit skips what can't be wrong:** a section whose every word and number is in the PDF's own text, and that has no maths, code or table, came from that text (no OCR), so there is nothing for a proofread to find. Most pages of digital PDFs are like that; scans and screenshots are still audited in full. Counted as `settled by the text layer`.
- **Marker's own LLM steps keep twice as many requests in flight:** while other workers are in OCR, the LLM's slots would otherwise sit idle.
- **More LLM slots when the GPU has room:** the notebook tries the vision LLM with 5 parallel slots per T4 first (more requests decoded together). It falls back to 4 if the server doesn't start, fails its test, or leaves less than `LLM_MIN_FREE_MB` (700 MB) for Surya on the same GPU. Free memory is checked right after the server starts, before its speed test, so a variant that doesn't fit costs only its start-up, and it is reported in one line. Measured on a T4 next to Surya with 8 slots: 4 LLM slots leave 1731 MiB and 6 leave 431 MiB (~650 MiB per slot), so 6 was always refused; 5 should leave ~1080 MiB.
- The page image is rendered once per page for both the review and the audit.
- **A page's image is processed once, not once per call** (measured on the box). A page image is 1484 prompt tokens, which take 2.84 s of GPU time the first time and 0.05-0.07 s when the same server gets it again: llama-server keeps what it processed. Under real load the plain least-busy balancer spread a page's calls over both GPUs, so only 2 of 48 calls reused their image (173 s of prompt processing instead of about 26 s). Now:
  - the load balancer sends a request with an image to the server that last had it, unless that server is clearly busier (`LB_SPILL` = 3 more requests in flight; 6 left one GPU 15-20 points less busy in the full-suite runs); `/lb-status` shows how often affinity held;
  - a page's audit sections and its second looks go one after the other, each reusing the image the previous call left. Many pages are in flight at once, so the GPUs stay busy;
  - the vision-LLM servers get a bounded host-RAM prompt cache (`LLM_HOST_CACHE_MB` = 2048 each), so an image a slot had to give up can be restored instead of processed again. Surya's servers keep none, since their crops never repeat. The unbounded default (8 GB per server) once filled the box's RAM.
- **Model requests in flight are capped per worker** (`LLM_INFLIGHT` = the box's LLM slots): one worker alone can fill every slot, but the nested pools (figures × graph answers, review × audit) can no longer queue hundreds of requests, where one waiting past its 900 s timeout would leave a page unreviewed.
- **Warm-ups at start:** each Surya server gets one page-sized OCR request, and the LLM test sends a page-sized image too, so the first job no longer pays for compiling GPU kernels (it was about a minute slower than the next).
- **Each job's report shows how the box was used** (`resources`, sampled every 2 s): GPU busy %, highest GPU memory, CPU busy %, and the lowest free RAM. The client prints it under each document ("box while converting: GPUs busy …").
- **Start slots are taken only for a waiting piece:** task files stay after their result is written, so "any task file" was always true and idle workers used up the RAM start slots while others converted; a new piece then waited up to a minute. Now a slot is claimed only when an unclaimed piece is waiting, and handed back if another worker took it.
- **No worker waits for another's second round** (measured in the full-suite runs: summed worker time ÷ workers was 426 / 681 / 958 s against 516 / 1068 / 1192 s of wall time, so workers were idle 17% / 36% / 20% of the time). The 27 pages were cut into 6 chunks for 5 workers, so one worker always had a second round while four waited. Chunk counts are now a multiple of the workers, rounded up while every chunk keeps `CHUNK_MIN_PAGES`, with sizes as even as possible: 27 pages make 5 × 5–6, 120 pages make 10 × 12 (5 workers) or 12 × 10 (6 workers).
- **A worker left alone can fill the GPUs:** each worker works on as many pages and figures at once as the box has LLM slots (10). The per-worker in-flight cap (`LLM_INFLIGHT`) keeps several busy workers from flooding the queues, so this only changes things when few workers are busy, e.g. the last chunk of a job. Before, a worker ran 2.5 × slots ÷ workers = 5 at a time, so the last chunk used half the slots. Marker's own LLM steps keep their concurrency (`MARKER_LLM_CONCURRENCY`).
- **Six workers:** the suite runs never had less than 7.7 GB of RAM free with 5 workers (about 2 GB per busy worker at its peak), so `MEM_PER_WORKER_GB` is 3.0 (was 3.5), and the 22 GB free at start now fits 6 (`WORKERS_PER_CPU` = 1.5 on 4 vCPUs). The start budget and the memory guard still protect the session.
- **Spare RAM becomes more workers:** Kaggle had 8-10 GB of RAM unused in every run. A worker spends much of its time waiting for the GPU models (descriptions, review, audit) with its CPU idle, so the box now runs up to `WORKERS_PER_CPU` = 1.5 workers per vCPU (6 on Kaggle's 4), as many as the free RAM holds at `MEM_PER_WORKER_GB` each. To keep the session safe, new pieces are budgeted: the pool publishes how many may start now, (free RAM − `MEM_PAUSE_FREE_GB`) ÷ `MEM_START_GB` (2.5 GB, what a piece grows by in its first minute). A worker must claim one of those start slots, which are exclusive files, and each slot counts for `START_WINDOW_S` (60 s) until the free RAM shows the piece. So several workers can't all start on the same free RAM at once. The existing guards stay: pause below 4 GB free, the largest worker stopped below 2 GB, and one worker may always run when nothing else does.
- **A diagram's graph is read while the figure is still being cropped and described** (for figures Marker's layout calls a Diagram; others only after their description says so). On the 2-case test this was the critical path; Figure 5.3 took 26 s instead of 51 s, with the same 19 arrows.

Measured on Cases 1 + 15 (2 pages, 4 figures, 2026-11-23): fast 148 s, balanced 159 s, accurate 162 s. On so few pages one diagram figure decides the time, so the qualities differ little; on long documents the per-page stages (Marker's LLM steps, review, audit) dominate. All three fixed `\sqrt[2]` and drew Figure 5.3's chart completely. Only fast kept the page's ceiling ⌈…⌉ in exercise 49b: Marker's LLM step had turned it into a floor in the other two. Since then a rewrite (Marker's LLM steps or the page review) may not change ceiling into floor or back; only the audit can, after a second look at the image.

Measured on Cases 1 + 5 + 15 (3 pages, 2026-11-23): **fast 156 s < balanced 186 s < accurate 223 s**, all at 97.8% text coverage. In every quality: Figure 5.3 complete (19 arrows), all 6 Case 05 table pictures in their cells, `\sqrt[2]` fixed. Fast and balanced kept the page's ceiling ⌈…⌉. In accurate, the audit's single second look "confirmed" ceiling → floor, and two fixes taken from the test page's ground-truth line stripped maths and italics from a caption. Marker's inline-maths rewrite also turned the polygon formula into inline maths, which the drawn-formula step then missed. Since then:
- the second look is asked twice, the two versions in both orders, and both answers must pick the new text;
- an audit fix may not remove maths (`$`) or Markdown formatting (`*`, `_`, `` ` ``);
- a paragraph that is only an inline formula of drawn shapes becomes a picture too.

Re-run after those fixes (Cases 1 + 5 + 15): **fast 120 s** (warm; 179 s as the first job after the box started), **balanced 144 s**, **accurate 200 s**, all at 97.8% text coverage. Every quality now has Figure 5.3's full chart, all 6 table pictures, no `\sqrt[2]`, and the page's ceiling ⌈…⌉. In accurate, the audit's formatting guard refused 2 bad fixes and the two-way second look confirmed only the right one. The first job after a box start is about a minute slower (servers warming up), so compare qualities on a warm box. Accurate still missed the polygon picture: after Marker's inline-maths rewrite the page had more drawn-formula blocks than formulas, and they were paired by count. They are now paired by content (shared words and symbols).

Third run (warm box, 5 LLM slots per T4 = 10 in all): **fast 112 s, balanced 203 s, accurate 213 s**. All three have the same results (full Figure 5.3 chart, 6 table pictures, no `\sqrt[2]`, the page's ceiling, 97.8% coverage) except the polygon picture in accurate. Marker's inline-maths rewrite had left that formula inside its sentence's paragraph. Drawn formulas are now found as maths spans (with a short "Q =" lead), wherever they sit, and only the formula is replaced. A formula still left as it was is reported (`drawn_formulas_skipped`).

Fourth run (warm box, 5 workers from the spare RAM, 10 LLM slots): **fast 129 s < balanced 165 s < accurate 206 s**. **All three now give the same result**: Figure 5.3's full chart (19 arrows), all 6 table pictures, no `\sqrt[2]`, the page's ceiling ⌈…⌉, the polygon formula as a clean picture with its description, and 97.8% coverage. A 3-page document is one piece (documents under `SPLIT_MIN_PAGES` = 8 pages are not split), so the extra workers don't show here; they help on long documents and batches of files.

To measure the trade-off on your own document: `python dev/compare_quality.py DOC.pdf`. Each quality goes into `test_out/quality/<quality>`, and an existing finished folder is reused. It prints wall time, worker time per stage, pages rewritten, audit fixes, text coverage, and a score when an optional scorer `dev/suite_checks.py` exists (the Doc2MD test suite's is not published).

## Engineering notes

- **Not supported:** Apple `.pages/.key/.numbers`, `.mobi`, `.xps`, and password-protected files. Export those to PDF first.
- **`.xlsx` and other spreadsheets** become one Markdown table per sheet. Charts inside spreadsheets are not extracted. Very wide sheets give very wide tables.
- **Office → PDF → Markdown** reconstructs headings from the layout, so heading levels can differ from the Word styles. Hyperlinks in `.docx` survive only with `--office native`.
- **DjVu** pages are always OCRed: the hidden text layer is not reused. Expect `balanced`/`vllm` speed, not `fast`.
- **Equations embedded as images** (old MathType objects) are recognised by the VLM from the rendered page. That is good, but not perfect, so check them.
- **One- and two-page documents and single images** keep their page header and footer: with nothing repeating from page to page, a banner or footer is content, not a running header.
- **Page review counting:** a word the PDF's text layer has may appear up to (draft count + layer count) times, so a footer Marker dropped can come back. Numbers still have to match exactly. A code fence's language (```` ```r ````) is ignored only at the start of a line; inline ```` ```mermaid ```` in text is a word.
- **Page review, paragraph by paragraph:** when a rewrite fails the check as a whole, each changed paragraph group is checked on its own. The groups that pass are used; for the rest, the draft stays. On Case 03 this kept the fixed Equation 2.13 (`ε`→`\hat{e}`, `λ`→`\lambda`, `\tag{2.13}`) while the made-up "clean" version of a garbled printed line was refused. The comparison treats `λ`, `\lambda` and `𝜆` as the same word, and an OCR's `ε` for `ê` as `e`; Greek words are left alone. A rewrite that unescapes `\$` is refused, because text would turn into maths.
- **Sub-figures:** "(a) Noisy unoriented data set" under a panel is its caption. The describer also gets the whole figure's caption ("FIGURE 2.8: …"), and the previous panel's caption is no longer passed as "text before it".
- **Equation numbers:** "(7.3)" on the line after a display equation, `\quad (7.5)` left outside it, and `\quad \text{(7.7)}` inside it all become `\tag{7.3}` inside the equation, shown at the right by GitHub, KaTeX and MathJax. A bracket that closes the formula, `$$` printed as text, and code are not touched.
- **Marker's LLM commentary:** a reply that talks *about* a block is refused, and Marker keeps its own text. This covers phrasings like "the equation is correctly formatted with math tags", "the LaTeX code is correct, but…", "should be placed after the equation" and "to ensure KaTeX compatibility". So is an equation that came back as plain sentences, with no maths left. On Cases 15–16 two such replies had replaced equations.
- **Pictures of text are transcribed in one answer first** (2026-11-23 full-suite run). The first tile-by-tile version cut the handwritten 1794 invoice into a 2×2 grid, which split every line and lost the prices. A dot leader then looped for thousands of characters, and the result replaced a good description just for being longer. Now one full-image transcription comes first: the invoice took 2 s and kept every line, price and the total "15 13 3"; Tagore's letter came out as clean continuous text. Tiles are used only when that answer is cut off or loops, as on the newspaper page, which then gave 7,518 characters with "COMMERCIAL HOTEL" and no loop. Transcription calls use llama.cpp's DRY sampler (a repeated word sequence costs more each time). Dot leaders become " … ", and a line repeated more than twice in a row is kept twice.
- **Shorter audit answers:** the audit often listed whole unchanged paragraphs as "fixes", and generating them cost GPU time. It now names only the wrong words with a few around them (under 60 characters), and its answer is capped at 800 tokens.
- **The page review's answer room** is now 2× the draft + 800 tokens (was 1.6× + 600, which cut 3 suite pages off). It is still bounded by the context.
- **Both GPUs equally busy:** in the full run GPU 0 was 92-94% busy and GPU 1 70-79%. With equal load the balancer always picked the first server, and affinity then kept those pages there. A new image's digest now breaks the tie.
- **A "|" inside a table cell** (maths such as `$|x|$` or a norm `\|w\|`, or code like `a || b`) used to split the row into extra cells. In a table row's maths it now becomes `\vert` / `\Vert`, and in its code `\|`, which GitHub tables read as a "|" in the cell. Text outside tables is not touched.
- **HTML left in tables:** an `<img>` with no picture (an icon Marker did not save) becomes its alt text, unless the same words follow it; `<b>`/`<i>` become `**`/`*`.
- **Headings:** a page-review rewrite of a paragraph that loses a `#` heading is refused, and the draft paragraph stays.
- **Text coverage** counts LaTeX printed as text (`\mathbf{e}_1` on the page). Before, every command name looked like a lost word.
- **Checkboxes:** a rewrite that changes how many task-list boxes are ticked is refused (Case 25: "[X] Step 1" came back unticked in run 3).
- **Tables checked against the page image** (after the page review, so nothing later undoes it). Each Markdown table is paired with Marker's Table block, in page order:
  - **Values in the wrong column** (Case 14: in a staggered table the lower rows had slid left): each row's values are found as ink blobs in the image, grouped into columns, and moved under the column they stand under. Values and their order are never changed. The fix is used only if the image has the same rows, values per row and columns. A vision-LLM version was tried and dropped: it "completed" the number pattern and gave made-up positions for small numbers.
  - **Pictures in cells** (Case 05: icons came out as `<img alt="surfel">` with no file): the ruled grid is found from its lines, and in each such cell the picture is everything above its label line. It is saved and linked as `![surfel](…)` in the cell. The vision LLM's boxes for these were too inaccurate (they drifted by half a cell).
- **Marker's equation rewrites with other letters:** if the rewrite's Greek letters share none with the original's (λ and ε came back as `\boldsymbol{\nu}` in run 3), it is a misreading, not a fix. Marker keeps its own text, and the page review then corrects it against the image.
- Tables are paired with Marker's Table blocks by shared words, not by order, so an extra table-like block on the page no longer stops the check. The report lists why a table was skipped (`tables_skipped`, `tables_error`).
- **Text-layer repair (every quality, no LLM):** a page whose layer disagrees with most of the lines it matches (3 or more differ, under half as many are the same) is left alone. The first version ("fewer are the same") skipped Case 15's page in the full suite, where the dropped footer left 2 same against 3 to fix. An old scan's own OCR layer can be worse than Surya's reading, and that is why Marker re-read it.
- **Text-layer repair and printed LaTeX:** a line with a plain `$` is normally maths and left alone. But when the PDF's own text line has that `$` too, the dollars are printed text (the test suite's LaTeX source), and the line is repaired. In the full-suite runs the OCR had left Case 15's title as `$(1 + \sqrt[2]{2})$$`, so the repair skipped it. Real maths never matches, because a rendered formula's PDF text has no `$`.
- **Text-layer repair, what it does:** a Markdown line that matches a line of the PDF's own text (90% or more, two joined layer lines too) but differs in a few characters gets those characters from the PDF. Case 15's `\sqrt[2]{2}` (OCR) becomes the printed `\sqrt{2}`, and words the audit wrongly "completed" go back to what the page prints ("Figure 2.1 T"). Never touched: maths, code, tables, quotes, images, list and heading markers, Markdown syntax, a line break's trailing spaces, punctuation swapped for other punctuation, a backslash from the layer, or a difference longer than 8 characters.
- **Formulas made of drawings** (Case 15: `Q = — + △ + □ + …` with pentagons cut by diagonals): a display formula with three or more shape commands (`\triangle`, `\square`, `\text{---}`…) is a drawing LaTeX can't write. Its area (Marker's Equation block) becomes a picture that is described like a figure.
- **The page's own text settles a refused paragraph:** a rewritten paragraph the strict check refuses is still used when every word and number of it is in the PDF's text and the matching stretch of that text agrees with the rewrite more than with the draft. Case 15: the OCR's `\sqrt[2]{2}` becomes the printed `\sqrt{2}`, while a rewrite that drops a real number matches worse and stays refused. A changed group with the same number of paragraphs on both sides is judged pair by pair. Printed `$…$` that a rewrite unescaped is escaped again.
- **Review prompt, maths symbols:** ceiling vs floor, `\leqslant` vs `\le`, hats and primes are checked against the image. A symbol LaTeX has no command for stays Unicode (`\text{▯}`), and the OCR's `0`/`O` for such a box may be replaced.
- **Stale list numbers:** Marker numbers list items itself, so the page's "2. Incremental development" came out as "1. 2. *Incremental development*". The extra number in front is removed (also in the page review's word check), so the list starts at the page's own number.
- `--llm` sends page content to Google's Gemini API. Without it, nothing leaves the Kaggle box except the results you download.
- **Figure crops:** Marker's layout boxes are often a little too tight, cutting off axis labels, legends and side text, and sometimes split one figure into pieces. `figures.py` re-crops every figure from the page. It grows each box over the ink connected to it (light-grey text and pale fills included, at most 90 pt per side), never into body-text paragraphs or captions (captions stay text in the Markdown; a "figure" that is really a caption is dropped; a strip of body text at a box edge is trimmed off; a box around a whole screenshot or page, with other figures and body text inside it, is dropped so each figure inside gets its own crop), merges pieces that overlap once grown, and crops at 300 DPI (Marker's crops are 192 DPI). On *Trees, Maps, and Theorems* this fixed every clipped label I checked. `--raw-figures` keeps Marker's own crops.
- **Vision LLM passes (default on):** the box runs **Qwen3-VL-8B** (Q6_K) next to Surya, one server per T4, both working in parallel. The model downloads in the background while LibreOffice installs. Marker sends it tables, tables that continue across pages, equations, inline maths, forms, complex regions, handwriting and heading levels. It also describes every figure in a `> **Figure content:**` quote under the image, so charts and diagrams aren't images only:
  - **First, a sentence or two on what the figure is and what it shows or explains.**
  - **Then everything inside it:** every label, number and value; a schematic's components with their values and connections; a chart's axes and series values; a table as a Markdown table; code as a code block (not copied again when the same code is printed in the text).
  - **Flowcharts, UML activity/state diagrams, workflows:** a second, focused call reads the graph on its own: every node (start, end, box, decision, fork/join bar) and one arrow per arrowhead. Several side-by-side diagrams are kept apart, leftmost first, and dotted "zoom" lines are recorded as "box X is shown in detail in Diagram N". What made this reliable, found by trial on the test suite:
    - the graph is read from the crop *before* it is tightened. With some room around it, Fig 5.3 came out right in 4 of 4 answers; the tight crop gave 0 of 4, with fork/join bars missed and diagrams out of order;
    - it is asked 3 times at once, and the answer with the most shapes and arrows is kept;
    - a second look is shown the arrows found so far and asked only for missing ones: feedback arrows, branches off a shared line, arrows at bars. On a waterfall where the first answers had only the 4 forward arrows, it found all 4 feedback arrows in 3 of 3 tries. On a graph that is already complete it sometimes invents arrows (fork → join), so a proposed arrow is added only if both ends are labelled boxes and two independent checks both propose it;
    - asking the model to list box labels first made it worse (it looked at text, not lines and bars), so that was dropped.

  Code then writes the details from that graph:
    - the arrows in words, the main flow first ("start → Conduct meetings → … → Formal prioritization? → (Yes) Use QFD … → Create use cases → end"), then each branch or feedback arrow ("Formal prioritization? → (No) Informally prioritize requirements → Create use cases"); a loop is closed ("… → Operation and Maintenance → Requirements Definition");
    - a ```` ```mermaid ```` flowchart, placed under the quote, not inside it, because many viewers draw no Mermaid inside a quote. Several diagrams sit side by side (`flowchart LR`, each `direction TB`, linked subgraph to subgraph). UML start is a solid dot, end a bull's-eye, and fork/join a black bar. The style classes avoid `end`, a Mermaid keyword that breaks the whole chart. Checked by rendering with Mermaid 12 in headless Chrome.
  - **The figure alone in its image:** before a figure is described, the vision LLM marks what in the crop is *not* the figure (caption, "FIGURE 5.3" tab, running header such as "30 Chapter 2 Software processes", horizontal rules, body text) and where the figure itself is. The crop is then snapped to whole ink shapes inside that box, so no stroke is cut. Long horizontal lines outside it count as page rules; lines inside it, like a feedback line or an axis, stay. If the new crop would lose ink that is neither marked as non-figure nor a thin rule, the crop is left unchanged.
  - **Logos and icons** are named in the image's alt text (`![KEY POINT logo](...)`), not in a quote block.
  - **Labels printed inside a figure's box** ("FIGURE 5.3" tabs, captions) are painted out of the crop, because the Markdown already has them as text. Bare numbers are never painted out, since they could be axis values.

  The model gets the figure's caption and the text just before it, so it can name the subject and read labels correctly ("Arduino Uno", not "ARUNO"), but it may only state what is visible. A failed or cut-off answer is asked again rather than skipped. On the first *Make Electronics* run, 47 figures had been left without a description and 348 of 476 descriptions were bare label lists. `--describe-again FILE.md` rewrites all descriptions of a finished file through the box's LLM without converting again, keeping the old file as `.md.bak`. Nothing leaves Kaggle. Without the local model the box uses Gemini if `GOOGLE_API_KEY` is set. `--no-llm` skips these passes (much faster) and `--no-describe` skips the figure text.
- **Page review (default on with the LLM):** after Marker, the figure fixes and the figure text, every page goes to the vision LLM. It gets three inputs: the page image, Marker's Markdown of that page, and, for PDFs with text, the page's text layer. It returns the final page:
  - words that were misread or left out are fixed;
  - headings follow the page's hierarchy, with lists, GitHub tables, LaTeX maths (`$...$` and `$$...$$`) and fenced code;
  - lines broken by the layout are joined into paragraphs.

  Figures, their content quotes and link anchors are replaced by `<<KEEP n>>` tokens first, so the model can't drop, move or rewrite them. A rewrite is used only if it loses and invents nothing. Words are compared one by one, short ones like `9V`, `mA`, `IC` included, and LaTeX commands are ignored, so `1.2K` and `1.2\text{K}` match:
  - every token appears exactly once;
  - every number in the draft is still there, as often as before, and no new number appears (catches a changed value like 9V → 6V or 20 mA → 2 mA);
  - no word is added that is in neither the draft nor the page, except a near-spelling of a word it replaces (an OCR fix);
  - at most 1% of the draft's words (2 minimum) may disappear, and only words that aren't on the page itself (OCR junk);
  - it covers at least as much of the PDF text layer as the draft did.

  The model often drops or repeats a token. Repeats are removed, and a dropped token goes back next to the text that surrounded it in the draft; on *Make Electronics* this had cost 27 of 96 rewrites. If any other check fails, the page keeps Marker's version. The report shows `pages_rewritten` and, for the others, why they kept the draft (`pages_kept_draft`). Afterwards a deterministic tidy-up runs over the whole file:
  - leftover `<math>` tags become `$`/`$$`;
  - headings, tables, display maths and code get blank lines around them;
  - unclosed code fences are closed;
  - repeated blank lines are collapsed (never inside code).
  - a paragraph cut by a page or column break is joined back when the first part stops without punctuation and the next starts in lower case ("because I consider it" + "the most essential…");
  - `- • item` double bullets become `- item`;
  - `[text](#)` links with no target become plain text;
  - dollar amounts are escaped (`\$34.99`), so "US $34.99 CAN $40.99" isn't rendered as a formula, while `$5$` and `$1 + 20\% = 1.2\text{K}$` stay maths;
  - display maths inside a table row stays inline, so the table doesn't break;
  - code blocks are never touched by any of these clean-ups.
- **Heading levels from the PDF outline:** each page is reviewed on its own, so the model can't see the book's structure (*Make Electronics* came out with chapters, experiments and their sections all as `##`). When the PDF has bookmarks, their levels are applied:
  - a heading that matches a bookmark on its page (±1) gets that bookmark's level (chapter `#`, experiment `##`, section `###`);
  - a heading the outline doesn't list goes one level below the entry it follows;
  - a short paragraph that is exactly a bookmark title becomes that heading;
  - a heading that repeats the title of a section it's already in (a running page header) is dropped.

  On *Make Electronics*: 482 headings matched, 23 promoted, 20 running headers dropped.

  The client runs the same tidy-up again on every finished file, including batches joined on your PC and output from an older box. On the whole file it also removes `<span id="page-…">` anchors that no link points to (Marker writes one per heading; only clutter).

  Images larger than 2400 px on their long side (a full page at 300 DPI) are scaled down, so figure crops keep their detail. A page too dense for the LLM's context is reviewed in parts, each with the full page image.
- **Languages (any Unicode script):** Surya's OCR and layout read 90+ languages, and Qwen3-VL is multilingual. Around them:
  - **Text checks by script:** the coverage and page-review checks compare words in a way that suits each script:
    - Bangla and other Indic scripts, Arabic and Hebrew: vowel signs and marks stay with their letter, so a changed vowel (গান → গুন) is caught;
    - Chinese, Japanese, Thai, Lao, Khmer and Myanmar, and any other long run without spaces: character by character, so one changed character is caught unless the PDF's own text shows it was an OCR fix;
    - digits stay in their script (১০ is not 10).
  - **Length budget:** for Bangla, CJK and other non-Latin text it allows about 1.3 tokens per character, so pages aren't cut off.
  - **Same language as the document:** the page review keeps the page's language and script and never translates. Figure descriptions are written in the document's language, with labels exactly as printed. Captions like "图3", "Рис. 5", "চিত্র ৪" and "شكل 3" reach the describer as context.
  - **Page breaks:** a paragraph split by a page break is joined back in any script when the page ends without closing punctuation (。 । ۔ ። … included). Lower-case continuation is recognised in every cased script (Cyrillic, Greek, accented Latin).
  - **Old Bangla PDFs:** PDFs typeset in Bijoy fonts (SutonnyMJ…) have a text layer of Latin gibberish ("Avwg evsjvq"). Such fonts are detected and those PDFs are read with OCR; the gibberish layer isn't used for any check (`forced_ocr` in the report).
  - **Text files in any encoding:** UTF-8, UTF-16/32 (with or without BOM), and legacy code pages (GBK, Big5, Shift-JIS, EUC-KR, Windows-1251/1253/1255/1256, TIS-620…), chosen by which decoding gives real writing.
  - **Zip files from Windows:** non-English file names stored in the local code page are decoded the same way, rather than kept as CP437 gibberish.
  - **Fonts:** the notebook installs Noto fonts for every script (core, extra, CJK, emoji), so rendering HTML, EPUB, DOCX or office files doesn't turn text into empty boxes.

  Limits: Qwen3-VL-8B is strongest in English and Chinese, and weaker in less common scripts (Bangla included), so its rewrites there fail the strict checks more often and those pages keep Marker's text. Vertical Japanese text depends on Marker's layout order. Code-page guessing for very short text can still be wrong.
- **Lessons from the 27-page Doc2MD test suite:**
  - **LaTeX in the LLM's JSON:** the model writes `\boldsymbol{\rho}` in a JSON string with one backslash, and JSON reads `\b` and `\r` as control characters (`oldsymbol{⏎ho}`). Before any LLM JSON is parsed (Marker's steps and the figure descriptions), a lone backslash before a LaTeX command name is doubled.
  - **Marker's own LLM steps are checked too.** Inline maths, equations and tables used to be rewritten unchecked: `\sqrt{2}` became `\sqrt[2]{2}`, and once an equation was replaced by "The equation in the image appears to be…". Every answer is now dropped (Marker keeps its own text) when it talks about the image instead of transcribing it, or, for a text block rewritten for its maths, when it changes a number or invents or loses words. Rejections are counted in the report (`marker_llm_rejected`).
  - **Text layers that can't be trusted are OCR'd:** glyphs without Unicode (`····· ···`, U+FFFD, private-use characters) and old Bijoy fonts. The report gives the reason (`forced_ocr`), and those text layers aren't used in any check.
  - **Indic text repaired from the PDF's own text:** Marker's text extractor stores Indic vowel signs in visual order (আমাদের came out as আমাদরে, ফেব্রুয়ারি as ফব্রুয়ারি), and OCR gave the same result. pdfium reads the same PDF correctly. Per page, when pdfium's Indic words are well-formed (no vowel sign at a word start or after another vowel sign):
    - an output word with the same consonants as exactly one pdfium word is replaced by it;
    - a short garbled stretch between matching words is replaced by pdfium's words.

    On the test suite's Bengali page, all 55 words then match the PDF (`indic_words_fixed` in the report). A vowel sign split off by a line break ("ঢাক ার") is joined back everywhere.
  - **The page review no longer removes page numbers:** it was told to drop running headers and page numbers while the check rejects any lost number, which cost most rewrites. A code block's language (```` ```r ````) no longer counts as an added word. Up to 12 rejected rewrites are listed with what differed (`review_examples` in the report), for tuning with real data.
  - **Screenshots and scans aren't figures again:** a PDF image whose area is already text is not added as a "missed" figure (each screenshot page used to appear twice). Figures that are mostly text already written out get a description of their diagrams, not of the running text.
  - **Every figure in an image is described**, not only the one a nearby caption names.
  - **Text-dense pictures** (a newspaper page) whose text doesn't fit in one answer get a short summary plus their text read tile by tile at full resolution, so they're never left empty.
  - **Clean-ups:**
    - the OCR model's tokens (`<|713|>`) are removed;
    - a paragraph repeated 3+ times in a row (an OCR loop) is kept once;
    - `[X] Step` becomes a `- [x]` task list;
    - blocks of short lines (receipts, addresses, poems) keep their line breaks;
    - only one-line paragraphs are joined across breaks.
  - **Short documents use every worker:** PDFs of 8+ pages are split into parts of at least 4 pages (27 pages → 6 parts for 4 workers; before, 2 parts used only 2 workers).
- **No repeated work:** an image that appears more than once (a logo, a repeated icon) is described once and the description reused. Images smaller than 150 px (half an inch at 300 DPI: bullets, icons) aren't described. Tokens the model makes up are removed rather than costing the page its rewrite. Each worker keeps up to 2.5× the LLM's slots in flight (over all workers), so the LLM stays busy while other workers are in Marker's GPU stage.
- **Where the time goes:** each document's report row has `stage_seconds` (`marker`, `figures`, `describe_figures`, `page_review`, summed over its pieces), and the client prints the split at the end. `--no-review` skips the review (faster). The biggest model that runs at a usable speed on the T4s is the 8B; the 27B measured 1.9 tok/s, so the review uses Qwen3-VL-8B.
  - **Startup test:** each GPU's server is used only if it passes. The test warms up first (the first request also compiles the GPU kernels), then must read "42" from a test image exactly, twice, and must generate at least `LLM_MIN_TOK_S` (default 5) tokens/s once warm.
  - **Settings tried, fastest first (`LLM_VARIANTS`):** n-gram speculative decoding with flash attention and an 8-bit KV cache (5 slots, then 4), then without n-gram (4 slots), then plain (2 slots); the Q4_K_M file only if Q6_K can't start. N-gram speculation suits Marker's fixes, which mostly copy text from the prompt.
  - **Log:** section 7 prints, per GPU, the file, setting and warm tokens/s.
  - **Why not a bigger model:** Qwen3.8-27B was tested on the T4s. Split over both GPUs it ran at 1.9 tokens/s (0.3 with `-sm tensor`), so it isn't used.
- **Text coverage check (PDFs):** after converting, every word of each page's PDF text layer is looked up in the Markdown. `report.json` gets `text_coverage`, plus `low_coverage_pages` for pages under 90%, and the client prints a warning for those pages. On *Make Electronics* the plain `balanced` output already kept 99.88% of 119,976 words, and the rest were formatting (units like "68 μF", subscripts written as LaTeX). This finds lost *text*; figure content is covered by the figure step.
- **Figures the layout model misses (PDFs):** in `balanced` mode the CPU layout model missed embedded photos and diagrams on many digital pages. On *Make Electronics*, 107 of the 282 pages with images got no figure at all. The figure step now also reads every raster image the PDF draws (pdfium gives its exact position). Each one that no figure covers, and that Marker didn't already turn into a table, form, equation or code block, becomes a figure (`_page_N_Picture_9000+k`). It's placed right before its caption in the Markdown, or at the end of its page if it has no caption. On that book this recovers about 229 images on 121 pages (estimated before the table check, which removes the image-tables). Vector drawings (lines, not pixels) can't be recovered this way; use `--mode vllm` for those.
- **Figures in scanned books:** in `fast` and `balanced` mode the layout (and the figure detector) is Indra's CPU model. On a scanned 96-page book (*Trees, Maps, and Theorems*) it extracted **no** figures, and it laid the table of contents out as tables. `--mode vllm` uses Surya's VLM layout, which labels pictures, figures and diagrams, so use it for scans with illustrations. It needs the GPU server.
- **CUDA 13 on Kaggle:** the `llama-server` build now points CMake at `libcuda` and only uses a CUDA toolkit the GPU driver can run. If section 3 still prints `!!! VLM unavailable`, the box runs CPU-only (`"vlm": false` in `--health`).
- **Memory (system RAM):** when a Kaggle session's RAM is full, Kaggle restarts the whole notebook ("Your notebook tried to allocate more memory than is available"). This happened on *Make Electronics* with the LLM passes. The box now protects itself:
  - **GPU servers:** all four llama-servers load without memory-mapping (`--load-mode none` on current llama.cpp, `--no-mmap` on older builds), so model files go straight to the GPU instead of staying mapped in RAM. The notebook reads `llama-server --help` once and leaves out any optional flag the downloaded build doesn't know, printing a note, instead of failing every start with "invalid argument". A command line the server refuses is not retried with fewer slots.
  - **Prompt cache in RAM, bounded:** llama.cpp keeps up to 8 GB of old prompts in system RAM per server by default (`--cache-ram`). With 4 servers this filled the 30 GB session on *Make Electronics*, so it was first turned off (`--cache-ram 0`). Later measurements showed that a page's review, audit and second looks reuse its image (2.8 s of GPU time each time it is processed again), so the vision-LLM servers now keep a bounded cache (`LLM_HOST_CACHE_MB` = 2048 each). Surya's servers keep none: their crops never repeat.
  - **What counts as used:** only memory the kernel can't free: process memory plus tmpfs/shared memory. File cache, such as the model files the GPU servers just read, is excluded because the kernel drops it before it kills anything. Counting it made the guard pause a run on *Make Electronics* for nothing.
  - **Worker count:** set from the session's real limit (its cgroup, not the host's total) after the GPU servers start: `MEM_PER_WORKER_GB` (3.0) per worker, at most `WORKERS_PER_CPU` (1.5) per vCPU, keeping `MEM_RESERVE_GB` (3) free.
  - **Guard:** a separate thread checks every 0.5 s.
    - Below `MEM_PAUSE_FREE_GB` (4 GB free), workers start no new piece. If nothing is running, one worker may still start, so the box can't deadlock: an idle box doesn't get below the line by waiting.
    - Below `MEM_KILL_FREE_GB` (2 GB free), whatever actually grew is stopped:
      - A GPU server bigger than `MEM_GPU_SERVER_MAX_GB` (5; a healthy LLM server is about 2.3 GB plus its prompt cache) is restarted by the watchdog, and the workers keep their pieces.
      - Otherwise the biggest busy worker is stopped and its piece is converted again. It is reported as failed only after it was itself big (over 60% of `MEM_PER_WORKER_GB`) three times. A small worker that was stopped only to buy time doesn't use up the piece's tries.
    - Above `MEM_RESUME_FREE_GB` (6 GB free), all workers work again.
    - While paused, an idle worker that has grown well past its fresh size gives the memory back or restarts.
    - Workers mark themselves as the kernel's first choice to kill (`oom_score_adj` 1000), so if RAM fills anyway the kernel stops a worker (its piece is requeued) rather than the notebook kernel or a GPU server.
  - **Workers:** after each piece a worker gives freed memory back to the system (`malloc_trim`) and restarts itself if it stays above 3 GB.
  - **Batches with holes:** if any page of a batch failed, the client converts the batch again (3 tries). It is never marked done while pages are missing, so rerunning the same command fills it in, and the final document is reported INCOMPLETE until then.
  - **Chunks:** at most 24 pages each (`CHUNK_MAX_PAGES`), which keeps a worker's peak lower.
  - **Office and DjVu files:** rendered to PDF on the box first, one at a time, and then split into page chunks like any PDF. A 600-page `.docx` is no longer one huge piece, and no worker holds LibreOffice and Marker together.
  - **Visibility:** `--health` shows RAM used, free and file cache, plus the 8 biggest processes (to see where the memory goes). The notebook's 5-minute heartbeat shows RAM used/limit, the job's progress line says when work is paused for low RAM, and memory events are noted in the job's warnings.
- **Batches (long documents):** a document is uploaded once and stored on the box; office and DjVu files are rendered to PDF there and the box reports the page count. If the document is longer than `--batch-pages` (default: box workers × `CHUNK_MAX_PAGES`, e.g. 96), the client converts it **one batch at a time**:
  1. The batch's pages (one 24-page chunk per box worker; your PC's workers take over unstarted chunks) are converted.
  2. The result is downloaded and saved under `<name>/.<name>.parts/<first>-<last>/` with a `done.json`.
  3. At the tail of a batch (every piece started, some workers already free) the next batch is queued, so those workers keep going. At most two batches are open, each is saved as soon as it is complete, and the box still converts one piece per worker, so RAM use is the same. `--no-overlap` waits for each batch to be saved first.

  When all batches are saved they're joined in page order into `<name>/<name>.md` (images and metadata included) and the parts folder is removed. If anything stops the run (the box restarts, the PC sleeps), the same command skips every batch already saved. The box never holds more than two batches, and `report.json` gives one row per document with `batches`, total pages, coverage and any failed page ranges.
- **Tunnel loss:** if Cloudflare loses the tunnel (HTTP 530), the client retries for up to 10 minutes. It follows the box's newly announced address (the watchdog restarts the tunnel) and carries on with the same job.
- **Page chunks** are converted independently, so a table that continues across a chunk boundary (every 4–24 pages) stays as two tables. Set `SPLIT_MIN_PAGES=0` in `JOB_DEFAULTS` to never split. Only native PDFs with Markdown output are split.
- Upload limit is `MAX_UPLOAD_GB` (3 GB). A zip may hold up to 2000 documents, or 6 GB once unpacked.
